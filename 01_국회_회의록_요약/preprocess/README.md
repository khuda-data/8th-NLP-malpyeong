# 국회 회의록 요약 데이터 전처리

국회 회의록 대화 데이터를 요약 모델 입력용으로 전처리하는 파이프라인입니다.

## 작동 흐름

```
JSON 파일 로드
  ↓
안건 경계 탐지 (sentence_id 기준)
  ↓
발화 정제 및 태깅 (<결정>, <안건>, <쟁점>)
  ↓
SimCSE 기반 중요도 태깅 (<IMP>)
  ↓
프롬프트 템플릿 생성
  ↓
결과 저장 (TXT, JSON)
```

## 상세 작동 흐름

### 1단계: 파일 로드 및 매핑 생성 (`main.py`)

#### 1.1 JSON 파일 로드
- `data/` 폴더에서 JSON 파일 읽기
- 각 샘플 구조:
  ```json
  {
    "id": "sample_id",
    "input": {
      "speaker": [...],
      "conversation": [...],
      "issue": {"sentence_id": "...", "keyword": "...", "topic": "..."}
    },
    "output": "요약 결과"
  }
  ```

#### 1.2 다음 샘플의 sentence_id 매핑 생성
- **목적**: 같은 dialogue 내 여러 안건이 있을 때, 각 안건의 끝점을 정확히 찾기 위함
- **방법**:
  1. dialogue별로 샘플 그룹화 (dialogue 길이, 첫/마지막 발화 ID로 구분)
  2. 각 샘플의 `sentence_id`로 dialogue 내 인덱스 찾기
  3. 인덱스 순으로 정렬하여 다음 샘플의 `sentence_id` 매핑
- **결과**: `{sample_id: next_sentence_id}` 딕셔너리
- **사용**: 안건 경계 탐지의 **1순위 기준** (100% 정확도)

### 2단계: 안건 경계 탐지 (`boundary_detection.py`)

#### 2.1 시작점 찾기
- `sentence_id`로 안건이 시작되는 발화 인덱스 찾기
- dialogue에서 `utterance.id == sentence_id`인 첫 번째 발화

#### 2.2 끝점 찾기 (우선순위 순서대로)
1. **1순위**: 같은 dialogue 내 다음 샘플의 `sentence_id` (100% 정확도)
2. **2순위**: "의사일정 제N항" 패턴 + "상정" 키워드
3. **3순위**: 결정 선포 문장 ("가결되었음을 선포합니다" 등)
4. **3.5순위**: 안건별 종료 문장 ("이상 보고를 마치겠습니다" 등)
5. **4순위**: 회의 종료 문장 ("산회", "마치겠습니다" 등)
6. **5순위**: Fallback (기본값 50개 발화, 최대 100개로 제한)

#### 2.3 경계 검증
- `start_idx >= end_idx` 또는 범위 초과 시 경고 및 자동 조정

### 3단계: 발화 정제 및 태깅 (`preprocessor.py`)

#### 3.1 발화자 정보 처리
- **이름 정규화**: "홍길동님" → "홍길동" (님, 의원 등 제거)
- **역할 매핑**: `speaker.occupation` → 역할명 (소위원장, 수석전문위원 등)

#### 3.2 불필요한 발화 제거
- **엄격한 필터링** (기본):
  - 10자 이하 짧은 발화 (의사진행 제외)
  - 단순 반응: "네", "예", "그렇습니다"
  - 인사/예의: "감사합니다", "수고하셨습니다"
- **완화된 필터링** (빈 샘플 방지용):
  - 최소 길이만 체크

#### 3.3 태그 적용 (`tagging.py`)
- **`<결정>`**: 가결, 부결, 의결, 통과, 상정 등 결정 관련 키워드
- **`<안건>`**: 안건명/법안명 (최대 2회 태깅)
- **`<쟁점>`**: 논란, 문제점, 반대/찬성 근거 키워드

#### 3.4 발화 형식화
- `[역할] 이름: <태그>발화내용</태그>`

### 4단계: SimCSE 기반 중요도 태깅 (`importance_by_similarity.py`)

#### 4.1 모델 로드
- **모델**: `BM-K/KoSimCSE-roberta-multitask`
- 전역 변수로 한 번만 로드 (성능 최적화)

#### 4.2 유사도 계산
1. **요약 임베딩**: 정답 요약(`output`)을 SimCSE로 임베딩 (한 번만)
2. **발화 임베딩**: 각 발화를 SimCSE로 임베딩
3. **코사인 유사도**: 발화 임베딩과 요약 임베딩 간 유사도 계산

#### 4.3 태그 적용
- **임계값**: 기본값 0.5 이상인 발화에 `<IMP>` 태그 적용
- **중복 방지**: 이미 `<결정>`이나 `<쟁점>` 태그가 있으면 `<IMP>` 불필요
- **Fallback**: 요약이 없거나 모델 로드 실패 시 규칙 기반으로 전환

#### 4.4 Test 데이터셋 처리
- **문제**: Test 데이터셋에는 `output`(정답 요약)이 없음
- **해결 방법**: 요약 모델 학습 필요
  1. Dev 데이터로 요약 모델 학습
  2. Test 데이터에 대해 예측 요약 생성
  3. 예측 요약을 `output` 필드에 넣어주면 Dev와 동일한 방식으로 처리됨
- **현재 동작**: `output`이 없으면 규칙 기반 fallback 사용

### 5단계: 프롬프트 템플릿 생성 (`preprocessor.py`)

#### 5.1 태그 설명 추가
- `<IMP>`, `<결정>`, `<안건>`, `<쟁점>` 태그의 의미 설명

#### 5.2 요약 작성 규칙 명시
- 각 태그가 있는 발화를 우선적으로 포함하도록 지시
- 필수 포함 정보 목록 (의사일정 번호, 법안명, 결정사항 등)

#### 5.3 요약 길이 가이드
- 정답 요약(`output`)의 길이 분석 (문자 수, 단어 수, 문장 수)
- 비슷한 수준으로 요약하도록 지시

#### 5.4 최종 프롬프트 구성
```
다음은 국회 회의록 안건별 대화입니다.

태그의 의미는 다음과 같습니다:
- <IMP>: 요약에 중요한 발화
- <결정>: 의사진행 결정사항
...

【중요】요약 작성 규칙:
1. <IMP> 태그가 있는 발화는 요약에 우선적으로 포함해주세요.
...

【요약 길이 가이드】
원본 요약 기준: 약 250자, 45단어, 3문장 수준

대화:
[소위원장] 양승조: <결정>의사일정 제1항...</결정>
...

위 대화를 요약해주세요.
```

### 6단계: 빈 샘플 방지

- 전처리 결과가 비어있으면 완화된 기준으로 재처리
- 2단계 fallback으로 처리

### 7단계: 결과 저장 (`main.py`)

#### 7.1 TXT 형식
- 각 샘플별로 구분하여 저장
- 형식: `=== Sample N (ID: ...) ===\n전처리된 대화\n\n`

#### 7.2 JSON 형식
- 모든 샘플을 리스트로 저장
- 각 샘플: `{id, preprocessed_dialogue, prompt, output}`

## 사용 방법

```bash
# 기본 실행

# 특정 파일만 처리
```

## 입력 데이터 형식

### Train/Dev 데이터셋
```json
{
  "id": "sample_id",
  "input": {
    "speaker": [{"id": "speaker_id", "occupation": "역할"}],
    "conversation": [
      {"speaker": "발화자", "utterance": "발화내용"}
    ],
    "issue": {
      "sentence_id": 10,
      "keyword": "안건키워드",
      "topic": "안건명"
    }
  },
  "output": "요약 결과"  // 정답 요약 (있음)
}
```

### Test 데이터셋
```json
{
  "id": "sample_id",
  "input": {
    "speaker": [{"id": "speaker_id", "occupation": "역할"}],
    "conversation": [
      {"speaker": "발화자", "utterance": "발화내용"}
    ],
    "issue": {
      "sentence_id": 10,
      "keyword": "안건키워드",
      "topic": "안건명"
    }
  },
  "output": ""  // 정답 요약 없음 (또는 필드 자체가 없을 수 있음)
}
```

**참고**: Test 데이터셋에 SimCSE 기반 중요도 태깅을 적용하려면, 요약 모델로 생성한 예측 요약을 `output` 필드에 넣어주면 됩니다.

## 출력 형식

### 전처리된 발화
```
[소위원장] 양승조: <결정>의사일정 제1항 법률안을 상정합니다</결정>
[수석전문위원] 김종두: <IMP>법률안의 주요 내용은 다음과 같습니다...</IMP>
[위원] 홍길동: <쟁점>이 법안의 문제점은...</쟁점>
```

### JSON 출력
```json
{
  "id": "sample_id",
  "preprocessed_dialogue": "[소위원장] 양승조: <결정>의사일정 제1항...",
  "prompt": "다음은 국회 회의록 안건별 대화입니다...",
  "output": "요약 결과"
}
```

## 태그 설명

- **`<결정>`**: 회의 결정사항 (가결, 부결, 의결 등)
- **`<안건>`**: 안건명/법안명
- **`<쟁점>`**: 논란/문제점, 반대/찬성 근거
- **`<IMP>`**: 요약에 중요한 발화 (SimCSE 기반 유사도로 자동 식별)
